# Frontend module boundaries

Where frontend code goes, and which direction its imports go. `vue/MODULE-BOUNDARIES.md` holds
the short rule set that `vue/AGENTS.md` points to. This file holds the reasoning.

## Layers

From the bottom up:

1. `vue/src/lib/` — plain TypeScript: no component, no reactive state that outlives a call. The
   tokens, the HTTP client, formatters, parsers. It imports nothing else from `src/`.
2. `vue/src/use/` — composables. They hold reactive state and lifecycle. They import `lib/`.
3. `vue/src/components/` — shared components with no domain knowledge. They import `lib/` and
   `use/`.
4. Feature modules — one directory per bounded context, e.g. `vue/src/system/`. A module imports
   the three layers above it. It never imports another module.
5. The app shell — `vue/src/App.vue`, `vue/src/router.ts`, `vue/src/main.ts`, and
   `vue/src/plugins/`. It may import every module, because it assembles them.

## Placement rule

Put code in the lowest layer that can hold it. A helper that two modules need moves down to a
shared layer; it is not imported across modules.

- **`lib` or `use`?** If it calls a Vue reactivity or lifecycle API, it is `use`. Otherwise it is
  `lib`, even when only one composable calls it.
- A module that grows its own composables keeps them in the module (`src/<module>/use-*.ts`)
  until a second module needs them.

## Auto-import

- Every export of `src/use/` is a global, and so are the Vue, Vue Router and VueUse APIs. Do not
  import them by hand.
- Every component in `src/components/` is a global, named for its path: the directory is the
  namespace, so `src/components/page/NotFound.vue` is `<PageNotFound>`. Put components that share
  a prefix in a directory named for the prefix, and drop the prefix from the file names.
- A component in a feature module is not a global. Import it by its relative path. This keeps a
  module's components out of every other module's namespace.
- `vue/src/auto-imports.d.ts` and `vue/src/components.d.ts` are generated by the dev server and
  the build. Commit them: `pnpm type-check` reads them.

## Import specifiers

- Use `@/` for an import from another layer (`@/lib/api`). Use a relative path inside one module
  or one layer.
